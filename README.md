# autoXRAY-multi

Отдельные подписки для клиентов поверх [autoXRAY](https://github.com/xVRVx/autoXRAY). Своего установщика здесь нет: он скачивается при установке.

Выбор VPS, домен, мост и удаление сервера — в [README оригинала](https://github.com/xVRVx/autoXRAY/blob/main/README.md).

## Быстрый старт

Один раз поставить команду:

```bash
curl -fsSL https://raw.githubusercontent.com/Netlighter/autoXRAY-multi/main/autoxray-multi.sh -o /usr/local/bin/autoxray-multi && chmod +x /usr/local/bin/autoxray-multi
```

Чистый сервер:

```bash
autoxray-multi install вашДОМЕН.com
```

Уже есть сервер:

```bash
autoxray-multi enable
```

Дальше клиенты — короткими командами: `autoxray-multi add alice`, `autoxray-multi list`, `autoxray-multi remove alice`.

## Клиенты

| Команда | Что делает |
|:--|:--|
| `add <имя>` | Новый клиент и его ссылки |
| `remove <имя>` | Удалить клиента и закрыть ему доступ |
| `list` | Подписки, страницы, UUID и пароли Hysteria2 |
| `sync` | Заново применить список или шаблон после ручной правки |

Имя: латиница, цифры, `_` и `-`. В ссылке оно в нижнем регистре, поэтому `Alice` и `alice` — один путь. Последнего клиента удалить нельзя.

| Клиент | Подписка |
|:--|:--|
| первый, обычно `default` | `https://домен/<случайный-путь>.json` и `https://домен/default.json` |
| остальные | `https://домен/<имя>.json` |

Рядом лежит такая же страница `.html` со ссылками и QR. Страницу подписки копируют в Happ или v2rayTun.

Telegram Web Proxy, если его включили при установке, общий для всех.

Имена правят в `/usr/local/etc/xray/clients.txt`, по одному в строке, затем `sync`. Убрать лишний профиль из подписки можно в `/usr/local/etc/xray/multi/template.json`. Исходный UUID в этом файле не менять. Списки клиентов внутри `/usr/local/etc/xray/config.json` трогать не нужно: `sync` записывает их сам.

## Обновление

Только ядро Xray, ключи и шаблон остаются:

```bash
autoxray-multi update-core
```

Если autoXRAY2 запустили заново и он перезаписал конфиг, клиенты возвращаются так:

```bash
autoxray-multi enable
autoxray-multi list
```

Их UUID сохраняются. Ключи, которые установщик напечатал в этом запуске, не используются. Новый случайный путь становится ещё одной ссылкой первого клиента.

Полная переустановка со сменой ключей установщика: `autoxray-multi install --force вашДОМЕН.com`.

## Суть

`install` скачивает свежий [autoXRAY2.sh](https://github.com/xVRVx/autoXRAY/blob/main/autoXRAY2.sh) и запускает его как есть: те же вопросы про fingerprint и Telegram Web Proxy, тот же Nginx, сертификат и `config.json`.

Установщик делает одну подписку со случайным путём и одного пользователя. Multi забирает её как образец и больше не собирает протоколы сам. Каждому имени из списка подставляются свой UUID, свой пароль Hysteria2 и свой путь ссылки. Первый клиент получает ключи установщика, поэтому ссылка, которую тот напечатал, открывает подписку `default`.

В `config.json` те же люди добавляются во все VLESS-входы. `flow` сохраняется, если он был у образца. У Hysteria2 у каждого свой пароль.

Набор профилей не зашит. Сейчас это VLESS XHTTP TLS, VLESS RAW TLS VISION, Hysteria2 и по желанию Telegram Web Proxy, всё на 443 порту. Когда автор autoXRAY поменяет набор, новая установка подхватит его сама.

Старое меню конфигов 1–7 убрано. Оно включало REALITY, gRPC, WS и порт 8443, а в текущем установщике этого нет. Профиль есть у клиента, только если он есть в шаблоне подписки.

`enable` на уже стоящем сервере делает то же снятие шаблона, без повторной установки. Исходная ссылка при этом не ломается.

Обёртка не считает трафик и не отключает клиента по лимиту: для этого нужны 3x-ui, RemnaWave или PasarGuard. Мост RU → EU она не ставит, отдельные прокси Telegram на человека не выпускает. Если в `template.json` вручную заменить исходный UUID, `sync` остановится.
